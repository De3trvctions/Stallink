## 1. 范围与原则

销售日报是店铺工作台「04」的只读对账页：店主按自然日查看已落盘的订单与收款快照，必要时重新生成，并导出 CSV / PDF。它不是实时看板，也不把不同币种的金额加在一起。

Kel 已定、本文必须遵守的规则：

- 保留现有能力：起止日期（含首尾、最长 31 天）、查询或重新生成、币种筛选、导出 CSV / PDF、分币种汇总、优惠金额、待退金额等指标。现金长短款在指标卡、分币种汇总、CSV 这三处隐藏，PDF 保留。见下方 C-2 与 §4.6。**Kel 已定 2026-11-26 14:21**。
- 视觉沿用 classic（纸白、墨黑、钴蓝、宋体标题）。展场、店面风格只改 token，不另起布局。
- **R1–R4，Kel 已定（2026-11-26），全部按推荐执行：**
  1. 币种下拉的可见标签为「导出币种」。它只决定导出范围，不改变屏幕报表。
  2. CSV 按屏幕上的指标补齐；计数列表头统一为「数量」（不再用「订单数」兼写商品件数）。只使用现有快照字段，不新增统计口径。
  3. 分币种汇总补上各币种优惠，并单独指定列模板，避免和默认三列网格错位。
  4. 「今天」由服务端按店铺报表时区下发，并作为起始 / 结束日期控件的上限。**需要服务端提供今天的日期（按店铺时区）**，前端不再用浏览器本地日期充当今天。
- **问题 2、11，Kel 已定（2026-11-26，13:32），维持关闭：**
  - 问题 2 选 A：选「全部币种」时，CSV 仍然只导出主币种。导出控件旁提示「CSV 只包含主币种 {代码}」；CSV 文件名写明主币种，不得出现「全部币种」。规则见 8.3。
  - 问题 11：非主币种的件数和各类订单笔数维持现状，只在文案说明。分币种汇总下方加一句小字。
- **C-1、C-2，Kel 已定（2026-11-26）：**
  - C-2 选 A：**Kel 已定 2026-11-26 14:21**：指标卡、分币种汇总、CSV 这三处隐藏，PDF 保留。原因是实收和找零已经从前后端去掉，这个数目前一直是 0。位置与样式见 §4.6。后端须继续在快照里提供 `cashOverShortMinor`（根对象与各 `currencies[]` 行），供 PDF 使用。
  - C-1 选 A：CSV 保持 5 列（分组,币种,项目,数量,金额）不变，只删掉长短款那一行。
- 查询过程中的目标效果（来自验收，需在设计与后续前端中落地）：
  1. **390 宽下指标卡不横向溢出**，展场风格同样成立。五张卡按 W2：收款总额独占一行，下面 2×2。
  2. **热销商品名按中文正常换行**，不要一个字一行。
  3. **工具栏按自身宽度排**，分成「生成」和「导出」两组；**1280 宽视口下排成一行**。

设计时已按 `ui-ux-pro-max` 检索过仪表盘 / 空状态 / 表格 / 导出相关指引。技能推荐的深色「Data-Dense Dashboard」色板与字体系不采用，以免偏离 Stallink classic；采纳的是可访问性与适配规则：正文对比度 ≥ 4.5:1、焦点环可见、触控目标 ≥ 44px、不出现横向滚动、加载与错误可恢复、金额与件数使用等宽数字、尊重 `prefers-reduced-motion`。

## 2. 用户流程

角色：店铺管理员（`shop_admin`）。店员 / 收银员没有本页入口；误入或接口拒绝时走「无权限」。

### 2.1 主流程

1. 从工作台侧栏进入 **04 销售日报**。页面先向服务端读取「报表今天」（按店铺时区的自然日），把起始日期、结束日期的默认值和上限都设为这一天，再自动查询这一天。拿不到「今天」时不退回浏览器本地日期，走出错重试。
2. 需要看一段日期时，填写 **起始日期**、**结束日期**（含首尾），点 **查询日报**。区间最长 31 天，且不得晚于服务端下发的今天。
3. 查询成功后：
   - **只查一天**：不出现「逐日收款」列表，直接进入该日详情与工具栏。
   - **查多天**：先出现「逐日收款」列表（由近到远），摘要显示各日分币种收款或「未生成 / 查询失败」。点某一天，下方详情与工具栏切到该日；切换日期时币种下拉回到「全部币种」。
4. 若该日已有快照：展示报表（报表头、五张指标卡、必要时的分币种汇总、活动与场次、热销商品、收款方式）。
5. 店主可点 **生成日报**（尚未生成）或 **重新生成日报**（已有快照，会覆盖当日记录）。成功后用接口返回的快照更新该日，并给出确认：「YYYY-MM-DD 的日报已生成。」
6. 已有快照时，可导出：
   - 若当日快照含 **两种及以上币种**，工具栏出现带可见标签「导出币种」的下拉（默认「全部币种」）。**Kel 已定（2026-11-26）R1**：它只决定导出范围，不改变屏幕上的报表（报表始终按快照主币种展示指标，明细按币种分组列出全部币种）。
   - **导出当日 CSV**：向 `GET /api/admin/daily-reports/export` 拉取文件。**Kel 已定（2026-11-26）问题 2 方案 A**：选「全部币种」时，CSV 仍然只导出主币种的明细，PDF 则包含全部币种。导出币种下拉旁显示「CSV 只包含主币种 MYR」（代码取 `report.currency`）；CSV 文件名写明该主币种，见 8.3。列与行按第 8.3 节，与屏幕指标对齐。
   - **导出 PDF**：在浏览器内根据当前选中的一天和币种生成文件。首次导出若需下载字体，显示进度。
7. 店主保存或打印文件后结束。同一页可改日期再查，或再生成、再导出。

「今天」以服务端按店铺报表时区（`reports.timezone`，未配置时沿用吉隆坡固定偏移）下发的日期为准。**Kel 已定（2026-11-26）R4**：前端用这个日期做默认起止和日期控件的 `max`，不再使用浏览器本地的 `localToday()`。

### 2.2 异常流程

#### 加载中

进入页面时，先读取服务端的「报表今天」。这一步完成前，日期控件保持禁用（可先留空，不填浏览器本地日期）。拿到今天之后，再查询当日日报：日期控件和按钮进入忙碌状态，主区域显示 `role="status"` 文案「正在读取日报…」，并预留与报表头、指标卡相当的骨架位置，避免结果到达时版面大幅跳动。多日查询按每批 4 天请求；过程中不插空已返回的半截列表。超过约 300ms 才需要看到骨架；若系统开启「减少动态效果」，骨架不做闪动。若「今天」接口失败，显示出错并提供重试，不要用本地日期顶上。

#### 空日（尚未生成）

该日接口返回 `404` 且 `errorCode = report_not_generated`，视为正常空状态，不是错误。文案：「这一天还没有生成日报。」工具栏只保留 **生成日报**（没有导出）。多日列表里该日标注「未生成」，收款摘要留空。生成成功后就地换成报表。

定时任务会在配置的时点尝试生成前一日快照；空日只表示当前还没有可用快照，店主仍可手动生成（含当天、以及尚未被定时任务写过的历史日）。

#### 出错或断网

单日请求失败（网络、超时、`5xx`、或 `200` 但 `date` 对不上）时，该日在列表中标「查询失败」，详情区用 `role="alert"` 显示原因，并提供 **重试查询**（按当前区间重新拉取）。推荐文案：

- 断网 / 请求抛错：「无法连接服务，请检查网络后重试。」
- 超时：「网络响应超时，请检查网络后重试。」
- 服务端错误：「服务暂时不可用，请稍后重试。」
- 读到的日报日期与请求不一致：「日报数据无法读取，请重试。」
- 生成成功但返回日期不符：「生成的日报数据无法读取，请重新查询。」
- 导出失败：优先把接口错误码翻译成已有文案；非 JSON 则「导出失败，请稍后重试。」

起始 / 结束日期的 `max` 就是服务端下发的今天，日期选择器里选不到更晚的日子。若仍出现未来日或非法日（例如接口被绕过），服务端继续以 `invalid_date` 拒绝，错误出现在日期字段旁。

#### 无权限

本页只给店铺管理员。未登录或会话过期（`401 unauthorized`）：「登录已过期，请重新登录。」并提供去登录的动作。已登录但角色不够（店员、收银、平台账号等，`403 forbidden`）：「没有权限执行这个操作。」说明销售日报属于店铺管理员，并提供返回工作台或退出。不要只在顶上闪一句红字；错误区本身要可被屏幕阅读器读到（`role="alert"`）。

#### 导出缺字

PDF 使用主题配套字体。若文本里有字体未收录的字符，文件仍会下载，成功提示需写明替换数量，例如：「销售日报-2026-11-26-全部币种.pdf 已开始下载。有 3 个字符字体未收录，已显示为 □。」CSV 不走这套字体，不出现缺字提示。下载字体过程中按钮保持忙碌，并显示阶段：

- 「正在加载 PDF 组件…」
- 「正在下载字体 x.x / y.y MB（首次导出需下载，之后会使用缓存）」
- 「正在生成 PDF…」

失败时给出可重试的原因（组件加载失败、网络中断等），不要留下残缺文件却无说明。

#### 超过 31 天

提交查询前即拦截，不发请求。结束日期字段使用原生约束：`每次最多查询 31 天，请缩短日期区间。` 另外：

- 结束日期早于起始日期：「结束日期须在起始日期当天或之后。」
- 日期无效：「请选择有效的起始日期和结束日期。」

错误出现在结束日期旁（`setCustomValidity` + `reportValidity`），而不是只在页顶。

## 3. 信息层级

从上到下，只保留一条主路径：先选定日期，再看这一天的账。

| 层级 | 内容 | 作用 |
|------|------|------|
| 1 | 页面标题「销售日报」 | 定位。标题下不再放旧稿那句「每天 00:10 自动生成」的长说明；区间规则改由日期提示承担。 |
| 2 | 起始日期、结束日期、查询日报 | 唯一的查询入口。提示：「含起止日期，每次最多查询 31 天。」 |
| 3 | 逐日收款（仅多日查询时） | 在多张快照之间切换。当前日用强调描边，并标「当前日报」。 |
| 4 | 当日工具栏 | 左：所选日期。右：两组操作——生成；导出（可见标签「导出币种」、CSV、PDF）。币种提示紧跟其下。 |
| 5 | 报表头 | 眉题 `日期 · 主币种`，标题「当日订单与收款」，生成时间与来源（手动生成 / 定时生成），右侧戳记「含退款订单 / 无退款」。 |
| 6 | 五张指标卡 | 主信息。第一张「收款总额」用强调色，其余同等权重：订单数、售出件数、优惠金额、待退金额。屏幕不展示现金长短款；**PDF 保留**，见 §4.6。 |
| 7 | 分币种汇总 | 快照含两个及以上币种时出现。各币种独立合计，不跨币种相加。表下小字说明件数与状态笔数只按主币种统计。 |
| 8 | 活动与场次、热销商品 | 桌面并排，窄屏上下排列。均按币种分组。 |
| 9 | 收款方式 | 全宽，按币种分组。 |

金额一律用 `formatMoney` 的格式：`MYR` 为 `RM 1,280.50` 这类前缀（实现是 `RM ` + 两位小数，不用千分位也可，原型与实现保持两位小数、不用千分位），`SGD` 为 `S$ `，`CNY` 为 `¥ `。数字用等宽变体（`tabular-nums`）。

## 4. 布局与组件

整体落在工作台壳里：顶栏、侧栏、主栏。主栏最大宽 1080px。classic 侧栏为纸白色（与 `docs/design-v2/screens/` 编辑式图一致），当前项浅蓝底、钴蓝字。

### 4.1 日期查询

一行两个日期字段 + 主按钮「查询日报」（深色主操作，一页只有这一枚主按钮）。字段有可见标签，不把标签只放在 placeholder 里。窄屏两字段并排，按钮换到下一行并左对齐。控件最小高度 44px。默认值和 `max` 都是服务端下发的今天。提示：「含起止日期，每次最多查询 31 天。今天 YYYY-MM-DD 由服务端按店铺时区提供，不能选择更晚的日期。」

### 4.2 逐日收款

卡片式列表。每一行：日期、该日各币种收款（或「未生成 / 查询失败」）、动作「查看 / 当前日报」。整行可点，最小高度 48px，当前项 `aria-pressed="true"`，描边与浅强调底。390 宽时金额折到第二行，避免横向滚动。

### 4.3 工具栏（目标效果）

```
[2026-11-26 日报]          [ 重新生成日报 ]    |    导出币种 [ 全部币种 ▾ ] [ 导出当日 CSV ] [ 导出 PDF ]
                               生成组                         导出组
```

规则：

- 工具栏按子项自身宽度排列，**不要**让币种下拉 `width: 100%` 独自占一行。
- 「生成」与「导出」是两组：组内不拆开；组与组之间空隙大于组内间距，可用 1px 竖线分隔。
- 未生成时导出组隐藏；查询失败时生成与导出都隐藏，只保留重试。
- 只有一种币种时，不出现币种下拉。
- 下拉左侧（或上方）有可见标签「导出币种」，无障碍名称与之一致。**Kel 已定（2026-11-26）R1**。
- 多种币种且选「全部币种」时，在导出币种下拉或「导出当日 CSV」按钮旁显示提示：「CSV 只包含主币种 MYR」。主币种取 `report.currency`，随快照替换。可附一句「PDF 仍包含全部币种。」选了某一币种后，这条提示隐藏（CSV 与 PDF 都只含该币种）。文案用 `--muted`，字号至少 0.8rem、行高 1.55，对比度达到 WCAG AA；390 宽时正常换行，不得 `white-space: nowrap`，不得横向溢出。**Kel 已定（2026-11-26）问题 2 方案 A**。
- **视口 1280px 时整行排成一行**（含侧栏占用后的主栏宽度）。实现不应用「视口 ≥ 70rem 才 nowrap」这种与主栏实际宽度脱节的条件，否则会像验收截图那样拆成三行。
- 390 宽允许换行，但按组换行：第一行日期 + 生成，第二行导出组；导出组在极窄宽度下可再折，按钮仍保持 44px 高。

忙碌时所有操作禁用，生成中按钮文案为「正在生成…」，CSV 为「正在导出…」，PDF 为「正在导出 PDF…」。

### 4.4 指标卡（目标效果）

五张卡：收款总额（主币种）、订单数、售出件数、优惠金额、待退金额。每张卡：标签、数值、一行注释。**Kel 已定 2026-11-26 14:21**：指标卡、分币种汇总、CSV 这三处隐藏，PDF 保留。屏幕指标卡不展示「现金长短款」，见 §4.6。

栅格按产品经理 plan W2（前端已按此开工）排列，**不留空位**：

- 宽于 720px（含桌面 1280 与平板 768）：**3 列**、两行。第一行是收款总额卡（占两列）加旁边 1 张「订单数」；第二行 3 张等宽：售出件数、优惠金额、待退金额。
- 宽度 **≤720**（含 390）：收款总额卡单独占一行，下面其余四张排成 **2×2**。展场风格同样成立。
- 数值允许在格内换行（长金额如「S$ 1,280.50」也要完整可见），不得 `white-space: nowrap` 把格子撑出视口。优先缩小字号：`clamp` 在 390 下收款总额约 1.45–1.7rem，其余约 1.2–1.45rem。卡片与数值都是 `min-width: 0`。
- 展场风格给报表加了内边距和圆角卡片，内容区更窄，仍走同一套 W2 栅格；**390 宽不再保留侧栏轨道**（见第 6 节），把宽度交给报表。
- 加载骨架与正式指标卡同一套栅格、同样五格，避免结果到达时版面跳动。

收款总额注释：「17 笔已收款 · 0 笔待付款」。订单数：「已关闭 1 · 退款 1」。售出件数：「平均每单 RM 75.32」。优惠：「数量价与套餐优惠合计」。待退：「待确认退款的金额」。

### 4.5 分币种汇总、活动、热销、收款方式

区块标题用宋体，右侧说明用小号等宽字（「各币种独立合计，不跨币种相加」「按币种分组」）。币种组标签用大写间距的弱化字，如 `MYR`。

列表用网格，而不是「一律三列」去硬套更多字段：

### 4.6 PDF 中的现金长短款

## 8. 接口对照与字段说明

### 8.1 接口

| 方法 | 路径 | 用途 |
|------|------|------|
| `GET` | `/api/admin/daily-reports/today` | **需要服务端新增（或挂到现有工作台引导接口上，字段相同）。** 返回店铺报表时区下的「今天」，供页面设默认起止日期和控件上限。见 8.4。 |
| `GET` | `/api/admin/daily-reports?date=YYYY-MM-DD` | 读某日快照。成功体即下方 `Report`。`404 report_not_generated` 为空日。`400 invalid_date` 为非法或未来日。 |
| `POST` | `/api/admin/daily-reports` 体 `{ "date": "YYYY-MM-DD" }` | 生成或覆盖该日快照，`source` 为 `manual`。成功返回完整 `Report`。 |
| `GET` | `/api/admin/daily-reports/export?date=YYYY-MM-DD&currency=MYR` | 导出 CSV。`currency` 可空（服务端回退为主币种）。`400 invalid_currency` / `invalid_date`，`404 report_not_generated`。列与行按 8.3 节。 |

读快照、生成、导出仍走 `shopAdmin`。「今天」接口同样只给店铺管理员。前端按日请求日报，多日时每批 4 个 GET，不存在「一次拉区间」的接口。PDF 不走服务端，由浏览器根据已加载的快照生成。

### 8.2 快照字段（前后端一致的部分）

服务端 `DailyReport` 与前端 `Report` 的 JSON 字段名一致，均为 camelCase：

`date`, `generatedAt`, `source`（`manual` \| `scheduled`）, `currency`（主币种）, `orders`, `paidOrders`, `pendingOrders`, `closedOrders`, `refundOrders`, `itemsSold`, `revenueMinor`, `discountMinor`, `refundMinor`, `cashOverShortMinor`（屏幕指标卡、屏幕分币种汇总和 CSV 不展示，**PDF 保留**，后端须继续提供，见 §4.6）, `cashTenderedOrders`（录了实收的单数，见下；PDF 用来判断是否显示「—（未录实收）」）, `averageMinor`, `currencies[]`, `events[]`, `topGoods[]`, `payCodes[]`。

金额皆为 **分（minor）** 的整数，界面和 CSV 再格式化为两位小数的主单位（与 `minorToMajor` / `formatMoney` 一致，CSV 仍不强制千分位）。

- `currencies[]`：`currency`, `orders`, `paidOrders`, `revenueMinor`, `discountMinor`, `refundMinor`, `cashOverShortMinor`, `cashTenderedOrders`。屏幕汇总与 CSV 不使用 `cashOverShortMinor`，**PDF 的分币种汇总仍使用**该字段和 `cashTenderedOrders`（§4.6）。后端须继续在每行提供这两项。没有待付款 / 已关闭 / 退款笔数，也没有件数、客单价。
- `events[]`：`eventId`, `name`, `currency`, `orders`, `revenueMinor`, `discountMinor`。
- `topGoods[]`：`currency`, `name`, `quantity`, `revenueMinor`。
- `payCodes[]`：`currency`, `name`, `orders`, `revenueMinor`。

屏幕报表始终用主币种填五张指标卡；`itemsSold`、`pendingOrders`、`closedOrders`、`refundOrders` 也只在主币种层面有值。PDF 若筛到非主币种，售出件数应显示「—」，并注明「件数仅统计主币种」。币种下拉（标签为「导出币种」）不改变屏幕报表，只影响导出。**Kel 已定（2026-11-26）R1**。**Kel 已定 2026-11-26 14:21**：指标卡、分币种汇总、CSV 这三处隐藏，PDF 保留。前端不要在屏幕指标卡、屏幕分币种汇总里渲染 `cashOverShortMinor`；后端 CSV 也不再输出这一行。PDF 继续读取快照根对象与各 `currencies[]` 行上的 `cashOverShortMinor` 和 `cashTenderedOrders`（见 §4.6）。后端必须继续下发这两个字段，供 PDF 使用。`cashTenderedOrders` 已在 `DailyReport` / `DailyReportCurrency` 中定义并写入快照，现有字段已够用，不再需要整天合计。前端用根对象的计数判断选全部或主币种时的总览指标卡，用各行自己的计数判断分币种汇总。前端 `document-model.ts` 现在按币种各自传入计数的做法，和 K-Q22 选 A 一致；只需核对它有没有把 0 显示成「—（未录实收）」。用 grep 只读核实：`overShortLabel`（第 53–59 行）在 `cashTenderedOrders === 0` 时返回「—（未录实收）」（第 56 行）；字段缺失（旧快照）不当成 0，仍按长款 / 短款 / 持平显示（第 55、57–59 行）。总览在选全部或主币种时传入根对象计数（第 87 行），选非主币种时传入该币种行计数（第 100 行）；分币种汇总每一行传入该行计数（第 112 行）。

### 8.3 CSV 导出（与屏幕指标对齐）

**Kel 已定（2026-11-26）R2**：CSV 按屏幕上的指标补齐；计数列表头由「订单数」改为「数量」。不新增统计口径，只使用 8.2 已有字段。金额仍为主单位、两位小数，文件带 UTF-8 BOM。

**Kel 已定（2026-11-26）问题 2 方案 A**：选「全部币种」或请求未带 `currency` 时，明细（按活动 / 按商品 / 按收款方式）和总览仍只出主币种；「按币种」段仍列出全部币种的合计（与现有 `renderDailyReportCSV` 一致）。选了某一币种时，总览、按币种和明细都只出该币种。

**Kel 已定（2026-11-26）C-1 / C-2 方案 A**：CSV 仍为五列「分组,币种,项目,数量,金额」，只从总览和按币种中删掉「现金长短款」行，不改列结构。

**文件名**按现有命名拟定：

- **CSV** 沿用现有服务端 `Content-Disposition` 形态 `daily-report-{date}-{currency}.csv`。`{date}` 为快照日期 `YYYY-MM-DD`；`{currency}` 必须是实际导出内容对应的 ISO 4217 大写三字母。
  - 选「全部币种」、主币种为 MYR：`daily-report-2026-11-26-MYR.csv`
  - 选 SGD：`daily-report-2026-11-26-SGD.csv`
  - **不得**写成 `daily-report-2026-11-26-全部币种.csv`，以免与「只含主币种」的内容不符。空 `currency` 时服务端继续回退为 `report.currency`，与现在一致。
  - 前端若响应头缺失，回退文件名用同一规则：`daily-report-{date}-{currency || report.currency}.csv`。
- **PDF** 保持现有 `reportPdfFilename`：`销售日报-{date}-{label}.pdf`。`{label}` 为币种代码，或在选「全部币种」时为「全部币种」。例：`销售日报-2026-11-26-全部币种.pdf`、`销售日报-2026-11-26-MYR.pdf`。多日（模型已支持，当前页面一次只导出当日）：`销售日报-{start}至{end}-{label}.pdf`。

表头固定五列：

```
分组,币种,项目,数量,金额
```

「数量」对应订单笔数或商品件数，由「项目」区分，不再用「订单数」去写 `quantity`。数量不适用的行留空，不要写 0 充数（例如优惠、待退、平均每单）。

**总览**（主币种，取快照根字段；若导出时选了非主币种，改用该币种在 `currencies[]` 里有的字段，没有的字段不出行：`pendingOrders`、`closedOrders`、`refundOrders`、`itemsSold` 仅主币种有值）：

| 项目 | 数量 | 金额 |
|------|------|------|
| 收款总额 | `paidOrders` | `revenueMinor` |
| 订单数 | `orders` | （空） |
| 待付款订单 | `pendingOrders` | （空） |
| 已关闭订单 | `closedOrders` | （空） |
| 退款订单 | `refundOrders` | （空） |
| 售出件数 | `itemsSold` | （空） |
| 平均每单 | （空） | `averageMinor` |
| 优惠金额 | （空） | `discountMinor` |
| 待退金额 | （空） | `refundMinor` |

不再单独写「已付款订单」一行，已付款笔数放在「收款总额」的数量列，与屏幕「N 笔已收款」一致。原先仅在 `refundMinor != 0` 时出现的「退款待处理」段取消，待退金额一律出现在总览（和按币种）里，金额为 0 也要写出。

**按币种**（各币种独立一行组，取 `currencies[]`）：

| 项目 | 数量 | 金额 |
|------|------|------|
| 全部订单 | `orders` | `revenueMinor` |
| 已付款订单 | `paidOrders` | （空） |
| 优惠金额 | （空） | `discountMinor` |
| 待退金额 | （空） | `refundMinor` |

**按活动**：每个场次两行——「项目」为活动名，数量为 `orders`，金额为 `revenueMinor`；下一行项目为「{活动名} 优惠」，数量空，金额为 `discountMinor`（0 也写）。

**按商品**：项目为商品名，数量为 `quantity`，金额为 `revenueMinor`。

**按收款方式**：项目为收款方式名，数量为 `orders`，金额为 `revenueMinor`。

商品名等仍须经 `spreadsheetText` 处理，避免表格软件把单元格当公式执行。

### 8.4 报表今天（需要服务端提供）

**Kel 已定（2026-11-26）R4**。**需要服务端提供今天的日期（按店铺时区）。** 现有实现里前端用 `localToday()`，服务端用 `reports.timezone` 校验，两边可能不是同一天。

约定最小响应（路径建议 `GET /api/admin/daily-reports/today`；若挂到已有的工作台引导接口，字段名保持不变）：

```json
{
  "today": "2026-11-26",
  "timezone": "Asia/Kuala_Lumpur"
}
```

- `today`：该店铺报表时区此刻的自然日，格式 `YYYY-MM-DD`。时区来自 `reports.timezone`，未配置时与现有 `reportDate` 一样回落到吉隆坡固定偏移。
- `timezone`：IANA 名称，供提示文案使用，例如「今天 2026-11-26 由服务端按店铺时区 Asia/Kuala_Lumpur 提供」。前端不拿它自己算今天，今天只以 `today` 为准。
- 权限与日报其他接口相同（`shopAdmin`）。未登录 `401`，无权限 `403`。
- 读、生成、导出接口继续拒绝晚于这个 `today` 的日期（`invalid_date`）。

前端：进入页面先取 `today`，把起始 / 结束的默认值和 `max` 都设成它，再自动查询这一天。这个请求失败时展示错误和重试，禁止退回浏览器本地日期。
