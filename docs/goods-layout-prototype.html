针对反馈「字体很小、平板不友好」，先定交互模型与断点字号规范，再落地到 /admin/goods。下方原型可切换两种模型与三档宽度，样本数据与线上字段一致。

01现状问题

字号偏小，平板距离下读不动

  • 壳层把标签压到 0.58–0.62rem（约 9.3–9.9px），正文 0.66–0.76rem（10.6–12.2px）。
  • 平板竖屏（768–1024）观看距离比手机远，9–10px 的 mono 标签基本看不清。
  • 输入框/按钮触控高度虽有 44px，但卡片内文字层级与留白不足，显得拥挤。

布局没用上平板宽度

  • 商品视图固定单列通栏行，768–1280px 宽度右侧大片留白，一屏只能看 3–4 件。
  • 同一商品的多场活动挤在一枚 chip 里，价格/余量与活动名粘连。
  • 视图切换、搜索、计数、添加按钮分散在三行，工具栏缺少统一分组。

02两种成熟模型对比

维度模型 A · 商品卡片网格 推荐默认模型 B · 密度行表
适用内容混合内容：封面图、名称、多场活动 chip、库存、状态、操作（本页正是这种）均匀数据：同构字段逐列对齐，适合大批量快速扫读与批量操作
平板表现2 列卡片，封面图做视觉锚点，竖屏握持也易点按行在窄屏退化为「图左文右」堆叠，列对齐被打散
信息密度中等：每卡留白充足，层级清楚高：一屏行数多，但单条信息展开有限
参考范式Shopify / Notion / 后台商品目录卡；Material 卡片自适应栅格Shopify 产品表；Linear / 后台数据表格；移动端表自动转卡片行
本项目建议用于「按商品」视图：一件商品一卡，承载多活动分布保留给「按活动」视图：同一场内商品逐行对齐价格/余量
结论：双模型并存——商品视图用 A 卡片网格做目录浏览，活动视图用 B 行表做分场核对。下方原型可分别点开查看。

字号调整（仅本页，不动全局壳层）

  • 标签 mono：9.3–9.9px → 11px，字距收到 0.04em。
  • 商品名：1.15rem 衬线 → 15–16px，行高 1.35。
  • meta / chip：9.6–10.6px → 11.5–12.5px，数字等宽对齐。
  • 库存摘要：从大数字条改为一行 mono 摘要，数字加粗 12.5px。

交互与可达性

  • 整张卡片可点进编辑；主操作按钮在卡片右下，次操作不挤入卡面。
  • 状态徽章不收缩、不裁切；售罄/低库存用 warning 色单独标注。
  • 搜索框、视图分段控件、主按钮同一工具栏换行分组；手机上占满行宽。
  • 焦点轮廓、悬浮底色沿用现有 token，不引入新圆角体系。

05确认后的落地范围

改动

  • 商品视图：清单行 → 卡片网格，三档断点栅格；字号按上表上调。
  • 工具栏：标题/计数、搜索、视图切换、添加按钮合并为一组响应式工具栏。
  • 卡片：封面 1:1、名称/meta、活动 chip、库存摘要、右下编辑按钮。
  • 行表视图：保留现有活动分组，仅同步字号与触控尺寸。

不动

  • 数据接口、库存配额与超卖校验、订单幂等链路。
  • 编辑弹窗结构与既有表单样式；全局壳层配色/字体 token。
  • 套餐卡片与收银台页面。
