# 商品与优惠按活动分组展示

## 背景

店铺工作台的“商品与优惠”页面现在通过“活动场次”下拉框一次查看一场活动的商品。店铺同时管理多场活动时，需要反复切换才能对比各场的商品、优惠和库存。

## 目标

在同一页面按活动分组展示店铺所有活动的商品上架信息。店员和店主能直接看到每场活动各自的价格、组合优惠、可售数量、已售数量和审核状态。

## 页面行为

- 新增商品表单继续保留活动选择器；提交时仍明确指定一个现有活动，或按当前流程同时创建新活动。
- 下方列表改为按活动分组。每组展示活动名称，以及可用的活动日期、地点/摊位号、状态和结算币种；组内仅列出该场活动的商品。
- 每个商品项显示该场商品的单价、组合优惠、可售/已售数量和平台审核状态。
- 商品名称、说明和总库存属于商品本身；活动价格、优惠、上架状态和分配数量属于该场上架记录。修改活动信息时只保存对应活动的 listing。
- 同一个商品参加多场活动时，在每个相关活动组各显示一项。商品资料保持共享；活动价格、优惠和库存配置互相独立。
- 没有活动时显示创建活动的引导；活动没有商品时只显示该活动的空状态。
- 各活动独立呈现加载和错误状态。某场加载失败时，其他活动仍正常显示；失败组提供重试入口。
- 布局继续适配桌面、平板和手机，不新增管理路由。

## 数据与实现边界

- 先调用现有 `GET /api/staff/events` 获取当前店铺的活动。
- 对每场活动调用现有 `GET /api/staff/events/{eventID}/listings`，按活动组装页面数据。
- 继续使用现有商品资料和 listing 更新接口；不新增数据库字段，不改变价格/优惠计算规则，也不改变平台审核流程。
- 页面通过活动 ID 和 listing ID 维护数据及保存状态，切换或重载期间避免旧请求覆盖新状态。

## 验收标准

1. 页面同时显示所有活动，每场商品不会混入其他活动。
2. 各活动的币种、价格、优惠和库存均取自对应活动的 listing。
3. 编辑并保存某场上架设置后，不影响同一商品在其他活动的活动级设置。
4. 同一商品参加多个活动时，商品资料保持一致；资料编辑仍作用于共享商品。
5. 单场没有商品或加载失败时，有明确的组级状态，其他活动仍可使用。
6. 新增商品仍可选择现有活动，原有同时创建活动流程继续可用。
7. 页面在桌面、平板和手机宽度下均可操作。

## 验证

实现后运行 Web 构建，并手动检查多活动分组、空状态、组级重试和单场设置保存。此次不增加或运行测试套件。
