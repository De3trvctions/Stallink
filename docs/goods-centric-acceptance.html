01问题定位与改造方案

改造前 · 不合理之处

  • 页面按活动分组：同一件商品在 N 场活动出现 N 张卡片、N 个编辑入口。
  • 编辑弹窗混合两层字段：名称/说明/图片/总库存实际全店生效，却按「本场商品」呈现，提示语误导。
  • 参加多场活动只能靠藏在弹窗里的「复制到其他活动」，看不到商品的全部活动分布，也无法从某场退出。
  • 保存 = 两次串行 PATCH（商品资料 → 本场上架），第二步失败留下「半保存」。
  • 没有全店商品接口：商品从所有活动下架后在页面上「消失」。

改造后 · 商品为中心

  • 默认「按商品」视图：一件商品一张卡片，含共享库存池（已售 / 已分配 / 可分配）与全部活动分布。
  • 编辑弹窗分层：「商品资料与共享库存（改一处，全部活动同步）」＋「活动上架与价格（各活动独立）」。
  • 弹窗内直接「加入新活动」「下架并释放本场配额」，活动分布一目了然。
  • 保存走新的单事务原子接口：商品资料 + 全部活动上架一次生效，任何一处失败整体回滚。
  • 保留「按活动」视图承载套餐与分场陈列；未参加任何活动的商品也可见、可管理。
方向决策：库存保持「总库存共享 + 每场配额」模型（各活动未售配额之和 ≤ 总库存，数据库事务内校验，杜绝超卖）。未改成无配额的真共享池——那需要深改预占/报表/测试，且配额制对摊主分货更可控。此前询问未获回复，按推荐方案执行，可随时再调整。

06已知边界与建议后续

本次刻意不做

  • 真·共享池（无配额）：保留配额制；如要改，需重构预占/校验/报表与大量测试，建议单独立项。
